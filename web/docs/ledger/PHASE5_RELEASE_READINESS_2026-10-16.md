## 5C — test-reliability audit (asynchronous audit writes and friends)
Found: `travel_attachments` E3 read a fire-and-forget audit row (CI failure, fixed in the previous phase), and the same class existed wherever tests read audit rows right after a route returned; root cause **in the application** (finding 9): audit writes were fire-and-forget. Fix = await them in the routes (deterministic completion), plus bounded polling helpers only where a test must wait for genuinely post-response work (`expenses_vertical.auditCount`, `expense_approval_policy`, `travel_attachments.audits`). Other timing assumptions reviewed: concurrency tests assert invariants (one winner / serial-order consistency), not scheduling. **Repeat-run evidence (5 consecutive runs each, scratch copy, disposable DB):** `travel_*` (5 files, 108 tests) 5/5 · `expense_approval_policy` 5/5 · `expenses_vertical` 5/5 · `cron_idempotency` 5/5 · `route_gap_closure` 5/5 · `employee_record_security` 5/5 · `mail_smtp_policy` 5/5 · `access_matrix_p2` 5/5 · `malformed_input_sweep` 5/5 · `shared_imap_policy`, `legacy_medical_inventory`, `release_ops_scripts` 3/3. Two repo guards also caught my own tests and were respected, not weakened: a real `CRON_SECRET` in a query string and a token-shaped invitation path both appeared in the dev-server access log (`z_final_log_secret_scan`, `receipt_cleanup` L1) → the tests now use in-process checks / short placeholders; a literal org id in a comment tripped `web_access_boundary` D2 → reworded.
